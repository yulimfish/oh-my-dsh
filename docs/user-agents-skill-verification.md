# User Agents skill root: source verification

The optional `userAgentsSkillRoots` adapter is default-off and accepts at most two explicit normalized absolute roots named `skills`. It does not infer HOME or enable upstream discovery automatically. Within the same Host registry layer it scans after configured OpenCode and Claude user roots, matching the user-root order of the pinned upstream skill discovery loader, not the separate command-merging precedence. Host scope precedence remains authoritative. Existing OpenCode and Claude numeric ranks are unchanged; Agents ranks are finite fractional values above 245 and below runtime rank 250, and after any configured OpenCode and Claude roots. Other providers can compete within that interval, and the extra roots consume shared scan and watcher budgets. Absolute-root observation watches lexical ancestors, potentially including filesystem-wide directories. An unrelated direct-entry change can invalidate the whole provider catalog and retire its watchers, causing rescans and watcher churn; no live event-rate measurement has been made. The inspected Host `fs.watch` callback supplies only an optional error, not a changed child name, so filtering such events by filename is not supported by that contract. Narrowing observation without losing retarget detection remains unresolved.

Focused project-provider and full Config/apply integration tests passed 147/147 using the workspace registry and temporary filesystem, including Agents-versus-runtime and first-versus-second Agents collisions, plus a simulated watcher callback and reload. Both `pnpm run check` and `pnpm run test:tool-outputs` passed 1,690 of 1,692 tests, with 2 skipped and 0 failed; the skipped cases require the optional Host preset registry unavailable in the workspace. `git diff --check` passed. These are source-only results; this change has not been installed or live-smoked in the Profile.
