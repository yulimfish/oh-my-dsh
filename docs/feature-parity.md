# Oh My OpenCode / OpenAgent parity ledger

> **Status: gap audit in progress.** This ledger is deliberately not a completion claim. Every upstream feature remains an acceptance item until it is implemented in `dsh-omo`, proven equivalent by a native DSH capability, or shown to be genuinely unavailable in the DSH host and given the closest safe adapter.

## Audit baseline

- Upstream source snapshot: [`oh-my-openagent` dev, commit `e50fc64a26f35ea07ceab26a8f23e8853fd2c4d6`](https://github.com/code-yeongyu/oh-my-openagent/tree/e50fc64a26f35ea07ceab26a8f23e8853fd2c4d6); feature and configuration references were fetched from that snapshot.
- Target runtime: DeepSeek Harness `0.2.0-rc.2`, Node `24.18.1`.
- Plugin baseline: `dsh-omo` commit `3398f8a`.
- “Native reuse” means DSH provides a comparable user-visible capability; it does **not** mean dsh-omo installs, configures, or has verified it. Host behavior must be checked independently before equivalence is accepted.

## Audit loop

1. Keep this matrix pinned to the source snapshot above; update the pin and re-audit when upstream changes.
2. For each row, obtain independent DSH API evidence, define observable acceptance tests, implement one coherent tranche, and commit it.
3. Commission a fresh adversarial subagent after each tranche. Resolve every valid finding, rerun tests/profile checks, and commit the remediation separately when useful.
4. Do not mark a feature complete based only on prompts, README claims, bundle composition, or mocked unit tests. Require an API-backed behavior test or a precisely documented host-native equivalence.
5. Completion requires every row to be implemented or independently evidenced as host-native / platform-incompatible, with no unverified row hidden in “out of scope.”

## Verified DSH reuse candidates

The target `ohmy-test` profile's composed standard agent preset exposes native subagent control/list, continuable `subagent`, fork, workflow, todo, goal, web search/fetch, skill filesystem/skill, jobs, session persistence, and JSON storage plugins. The current `dsh-omo` row is present in `dsh --profile ohmy-test --dump-config`; its plugin doctor reports v0.1.3. This proves bundle composition only, not feature-by-feature behavioral parity.

The installed RC2 `@deepseek-ai/dsh-subagent` type surface includes one-shot `start`, durable `startContinuable`, `sendMessage`, `interrupt`, `listChildren`, and `listDescendants`. The existing plugin uses only one-shot `start`; durable background control should be built on the host APIs rather than copied storage where they satisfy the acceptance criteria. The user's separate `desktop` profile includes `@deepseek-ai/dsh-experimental-agent-team-profile`; `ohmy-test` does not, so dsh-omo must detect/optionally integrate that capability rather than assume it is universally installed.
